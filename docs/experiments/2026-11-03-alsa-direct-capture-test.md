# Опыт: Прямой аппаратный захват с ALSA hw:0,2 без компонентов Яндекса (maind) — 3 ноября 2026

- Дата / ответственный: 2026-11-03 / Antigravity
- Основание в задаче пользователя: Рубеж H1 целевой архитектуры (`TARGET_ARCHITECTURE.md`, `GENERAL_PLAN.md`): доказательство независимого аудиотракта и освобождение аппаратного микрофонного интерфейса `hw:0,2` (`pcmC0D2c`) от vendor-демона `maind`.
- Ограничение пользователя: «real dinamick-mic noize tests not today, so let continue» — акустические тесты динамика и громкие микрофонные испытания не проводились; проведён цифровой захват тестовых пакетов и 1 секунды сырого потока с анализом каналов и RMS.

## Гипотеза и измерение

- **Гипотеза:**
  1. При работающем `maind --platformd` захват через ALSA `hw:0,2` блокируется с ошибкой `Device or resource busy`, так как `maind` монопольно держит дескриптор `/dev/snd/pcmC0D2c`.
  2. При контролируемой остановке `quasar_launcher2` и `maind` файл `/dev/snd/pcmC0D2c` освобождается, и ALSA-интерфейс `hw:0,2` (8 каналов, 48 kHz, S32_LE) становится доступен напрямую для собственного захвата.
  3. Для успешной работы с драйвером Amlogic Auge PDM требуется согласованная геометрия буфера: `buffer_size = 1024 frames`, `period_size = 512 frames`, `periods = 2`, `access = RW_INTERLEAVED`, `format = S32_LE`, `rate = 48000 Hz`.
  4. Нативный C-хелпер `mini_pcm_source` (5.2 КБ) способен непрерывно захватывать чистый поток без `maind` и без `yio_audio`.
- **Что не проверялось:** Физическое воспроизведение через динамик (согласно ограничению владельца); cold boot без модулей ядра.

## Preflight

- Устройство: Yandex Station Mini 1 (`YNDX-0004`), Amlogic A113X (armhf, glibc 2.23, ядро 4.9.68).
- Сеть: Wi-Fi ACAB (`192.168.1.110:2222`), прямой SSH-доступ.
- Штатные процессы до опыта:
  - `quasar_launcher2` (PID 1790)
  - `maind --platformd` (PID 1862, держал `/dev/snd/pcmC0D2c` на fd 139)
  - Вызов `arecord -D hw:0,2` при активном `maind` стабильно возвращал `audio open error: Device or resource busy`.

## Действия

1. Остановка процессов Яндекса: `killall -TERM quasar_launcher2 maind`.
2. Контроль дескрипторов: `ls -l /proc/*/fd/* | grep pcmC0D2c` показал полное освобождение устройства.
3. Анализ сбоя `arecord` (`set_params:1168: not enough memory`): стандартный `arecord` запрашивает буфер по умолчанию в 24000 фреймов, что отвергается ядром с `ENOMEM`.
4. Разработан и собран нативный хелпер `mini_pcm_source.c` с использованием `zig cc -target arm-linux-gnueabihf.2.23`:
   - Открытие `/system/vendor/quasar/libs/libasound.so.2.0.0` через `dlopen`.
   - Подавление отладочного мусора вендорной библиотеки (`ShareContextCreate`) в `stdout` во время открытия через временный редирект в `/dev/null`.
   - Точные согласованные параметры: `period_size = 512`, `periods = 2`, `buffer_size = 1024`.
5. Выполнен захват 1 секунды в `/tmp/clean_1s.raw`:
   - Записано ровно $93 \text{ периода} \times 512 \text{ фреймов} \times 8 \text{ каналов} \times 4 \text{ байта} = 1\,523\,712$ байт без посторонних текстовых включений.

## Результаты измерений

1. **Сырые сигналы с 4 физических микрофонов (Ch0..Ch3):**
   - Канал 0: RMS = 12079.6
   - Канал 1: RMS = 11738.7
   - Канал 2: RMS = 11629.0
   - Канал 3: RMS = 13195.0
   - Каналы 4..7: референсные/вспомогательные каналы.
2. **Результаты децимации (Decimator 3:1 + FIR + Avg4 beamformer):**
   - Выходной поток: 16000 Hz, 16-bit mono PCM.
   - Начальный период (0..100 мс): переходный процесс установления постоянной составляющей PDM.
   - Установившийся режим (500..992 мс): фоновый RMS тихой комнаты = **127.06** (около −48 dBFS), пик = 251.
   - Сигнал строго центрирован вокруг нуля, чистый, без клиппинга и без искажений.

## Вывод

Рубеж H1 доказан на реальном оборудовании: Станция Мини способна захватывать звук напрямую с микрофонного массива `hw:0,2` без запуска `maind`, `quasar_launcher2` и `yio_audio`.
