# План: Автономное воспроизведение музыки Spotify на динамике Яндекс Станции Mini 1

- **Статус:** draft (согласование с пользователем)
- **Дата:** 08.11.2026, Asia/Tbilisi
- **Репозитории:** `gpt-mini` (архитектура и документация), `mini-assistant` (Rust-реализация)

---

## 1. Задача и критерии готовности

### Главная цель
Яндекс Станция Mini 1 должна работать как полноценная автономная смарт-колонка:
при запросе пользователя *«Штучка, включи музыку»* (или включении трека через приложение Spotify) звук должен воспроизводиться **непосредственно через встроенный динамик самой Станции Mini**, а не через внешние ноутбуки или телефоны.

### Наблюдаемые критерии готовности
1. **Обнаружение в приложении:** В приложении Spotify на смартфоне или компьютере станция видна в списке устройств как отдельная смарт-колонка **«Яндекс Станция Mini»** (тип: Speaker).
2. **Воспроизведение из динамика:** При выборе станции в Spotify или по голосовой команде *«Штучка, включи рок»* музыка звучит из физического динамика станции Mini (`hw:0,0` через `mini_pcm_sink`).
3. **Приоритет локального устройства:** Если пользователь говорит станции *«Включи музыку»*, команда всегда направляется на саму Станцию Mini, даже если в аккаунте активны другие клиенты (ноутбук, планшет).
4. **Аудио-арбитраж (Barge-in / Ducking):** Когда играет музыка и пользователь произносит *«Штучка»*:
   - Музыка немедленно ставится на паузу (или приглушается), освобождая звуковой тракт.
   - Ассистент чисто произносит ответ («Слушаю», прогноз погоды, подтверждение трека и т.д.).
   - По завершении реплики ассистента воспроизведение музыки автоматически возобновляется.
5. **Приоритет будильника:** Звонок локального будильника безусловно прерывает воспроизведение музыки.
6. **Ресурсный бюджет:** Фоновый плеер и ассистент суммарно потребляют не более 50 МБ RSS из 236 МБ доступной оперативной памяти Mini; загрузка CPU в режиме воспроизведения не превышает 25%.

## 2. Исходное состояние и анализ проблемы

### Почему сейчас музыка включилась на ноутбуке
- В предыдущей сессии было реализовано управление через **Spotify Web API** (`api.spotify.com/v1/me/player/...`).
- Web API — это облачный пульт дистанционного управления: он посылает команды на *уже существующие* плееры в аккаунте Spotify.
- Поскольку на самой станции в фоновом режиме не был активен приёмник потока, метод `get_devices()` обнаружил единственное доступное устройство — ноутбук (`MacBook Pro (4)`), и передал команду воспроизведения туда.

### Имеющиеся наработки в проекте
1. **Собранный бинарник `librespot`:**
   - Версия v0.8.0, статически скомпилированная под `armv7-unknown-linux-musleabihf` (ELF 32-bit ARM).
   - Находится в `mini-assistant/target/librespot-arm32/librespot` (размер 18 МБ, проверен на Mini).
   - Поддерживает вывод PCM в stdout (`--backend pipe --format S16`).
2. **Аудио-пайплайн в `src/spotify/mod.rs`:**
   - Уже написан потоковый ресемплер `StereoResampler` (44.1 кГц стерео S16LE → 48 кГц стерео S16LE с защитным запасом 6 дБ для peak guard).
   - Написан модуль `forward`, перенаправляющий декодированный PCM в нативный `mini_pcm_sink`.
   - Написан механизм 5-минутных сегментов (`SEGMENT_BYTES` / `SEGMENT_AGE`) для защиты от переполнения буферов нативного драйвера Quasar.
3. **Авторизация OAuth PKCE:**
   - Веб-интерфейс на порту 8080 (`SpotifyWebServer`) генерирует PKCE-ссылки и успешно обновляет `refresh_token`.

### Уроки предыдущего опыта (06.11.2026)
- При изолированном запуске `librespot` с флагом `--disable-credential-cache` без сохранения сессии серверы Spotify отклоняли выдачу ключа дешифрования аудиопотока (`AUDIO_KEY_FAILED`).
- Решение: `librespot` должен запускаться с постоянным каталогом кэша учетных данных (`--system-cache /data/opt/mini-assistant/spotify_cache`), а скоупы авторизации должны явно включать `streaming`.

## 4. Этапы реализации

### Этап 1. Доработка авторизации и скоупов потокового аудио
- [ ] В `mini-assistant/src/spotify/local_server.rs` расширить список `SPOTIFY_SCOPES`:
  ```rust
  const SPOTIFY_SCOPES: &str =
      "user-read-playback-state user-modify-playback-state user-read-currently-playing streaming user-read-email user-read-private";
  ```
- [ ] Обеспечить создание каталога `/data/opt/mini-assistant/spotify_cache` с правами `0700` на устройстве.
- [ ] При первичной авторизации через веб-интерфейс `http://192.168.1.110:8080` сохранять сессию в кэш.

### Этап 2. Интеграция управляемого фонового сервиса `librespot` в `mini-assistant`
- [ ] Реализовать структуру `SpotifyReceiverService`:
  - Запуск `librespot` как дочернего процесса (`tokio::process::Command`):
    - `--name "Яндекс Станция Mini"`
    - `--device-type speaker`
    - `--backend pipe --format S16`
    - `--bitrate 160`
    - `--system-cache /data/opt/mini-assistant/spotify_cache`
    - `--zeroconf-backend libmdns`
    - `--autoplay off`
  - Захват `stdout` процесса (сырой PCM) и передача в потоковый ресемплер.
  - Автоматический перезапуск (supervision) при непредвиденном завершении с экспоненциальной задержкой.

### Этап 3. Аудио-арбитр (координация голоса, музыки и будильников)
- [ ] Реализовать координатор доступа к динамику (`AudioArbiter`):
  - Приоритеты: `Alarm` (1) > `Voice/Gemini` (2) > `Spotify Music` (3).
  - При поступлении аудио от Gemini или срабатывании wake-word:
    - Арбитр немедленно приостанавливает музыкальный рендерер и отправляет команду `SpotifyApiClient::pause()`.
    - Дает 200 мс на освобождение `mini_pcm_sink`.
    - Воспроизводит ответ модели.
    - По завершении реплики и закрытии окна диалога отправляет команду `SpotifyApiClient::resume()`.

### Этап 4. Принудительный выбор Станции Mini в Web API
- [ ] В `src/spotify/web_api.rs` переработать логику разрешения устройства:
  - Вместо выбора первого случайного устройства (`devices.first()`):
  ```rust
  let target = devices.iter().find(|d| {
      d.name.eq_ignore_ascii_case("Яндекс Станция Mini")
          || d.name.eq_ignore_ascii_case("GPT Mini")
  }).or_else(|| devices.iter().find(|d| d.is_active));
  ```
  - При любых вызовах воспроизведения без указания устройства (`play`, `resume`, `search_and_play`) адресовать поток на локальную Станцию Mini.

### Этап 5. Сборка, деплой и верификация на устройстве
- [ ] Скопировать бинарник `librespot` в рабочий каталог `/data/opt/mini-assistant/librespot` и сделать исполняемым.
- [ ] Собрать обновленный релиз `mini-assistant` под ARMv7 musl и задеплоить на Mini.
- [ ] Проверить по логам `assistant.log`:
  - Успешный запуск `librespot` и регистрацию mDNS в локальной сети.
  - Появление устройства в приложении Spotify на телефоне/ноутбуке.
- [ ] Выполнить живую проверку голосовых команд:
  1. *«Штучка, включи музыку»* → звук начинает играть из динамика Mini.
  2. Во время воспроизведения: *«Штучка, какая погода?»* → музыка встает на паузу, станция отвечает голосом, затем музыка возобновляется.
  3. *«Штучка, следующий трек»* → переключение следующей композиции на Mini.
  4. *«Штучка, пауза»* / *«хватит»* → остановка музыки и освобождение динамика.

## 6. Риски, ограничения и пути решения

| Риск | Влияние | Решение |
|---|---|---|
| **Повторение `AUDIO_KEY_FAILED`** | Поток пропускается, `PCM_TOTAL_BYTES=0` | Использование `--system-cache` и скоупа `streaming` при PKCE-авторизации; при необходимости запуск с сохранением сессии Zeroconf с телефона. |
| **Нехватка оперативной памяти** | OOM-killer завершает процесс | `librespot` компилируется без неиспользуемых фич, битрейт зафиксирован на 160 кбит/с, кэш аудиофайлов отключен (`--disable-audio-cache`), кэшируются только метаданные авторизации. |
| **Конфликт за ALSA `hw:0,0`** | Ошибка `Device or resource busy` при ответе голосом | `AudioArbiter` строго сериализует доступ: `mini_pcm_sink` музыки закрывается с маркером `END` до открытия рендерера голоса ассистента. |

## 7. Откат (Rollback)

- Если фоновый `librespot` вызывает нестабильность:
  - Отключаем запуск дочернего плеера в конфиге (`config.toml: [spotify] autostart_receiver = false`).
  - Процесс ассистента возвращается в режим управления внешними плеерами через Web API.
  - Прежний проверенный бинарник сохраняется в `/data/opt/mini-assistant/mini-assistant.bak`.
