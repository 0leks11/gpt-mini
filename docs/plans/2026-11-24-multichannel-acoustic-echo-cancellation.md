# План: Многоканальный алгоритм вычитания собственного эха динамика (M-AEC)

- Статус: in-progress (Фаза 1: проектирование и аппаратная верификация)
- Дата: 24 ноября 2026
- Репозиторий и владелец: `mini-assistant` (Rust) / `gpt-mini` (docs & infra)

## 1. Задача и критерии готовности

Создать встроенный в Rust-конвейер `mini-assistant` многоканальный алгоритм акустического эхоподавления (Acoustic Echo Cancellation, M-AEC), устраняющий собственное эхо динамика (музыку Spotify Soloist и речь TTS) из сигналов микрофонного массива.

### Что должен увидеть пользователь:
1. **Надёжный Barge-in:** Пользователь произносит «Штучка» обычным голосом (~65 dBA) с расстояния 1–3 метра прямо во время громкого воспроизведения музыки (75–85 dBA) через внешнюю базу, и колонка гарантированно откликается (вероятность срабатывания $\ge 90\%$).
2. **Отсутствие необходимости в ducking:** Больше не требуется программно глушить музыку (-14 дБ) вслепую, колонка непрерывно «слышит» пользователя сквозь собственное звучание.
3. **Прозрачность телеметрии:** В Web UI и через REST API (`GET /api/v1/acoustics/aec`) отображаются текущие метрики: ERLE (дБ), статус DTD (Double-Talk), задержка (мс).
4. **Спектрографический анализ (Time-Frequency Spectrograms):** Визуализация 2D Waterfall спектрограмм (до и после эхоподавления) в Web UI и выдача структурированных спектральных матриц (энергия по полосам 100..8000 Гц) через REST API и MCP для точной диагностики резонансов, искажений динамика и остаточного эха.
5. **Автоматический оптимизатор Hill-Climb (Coordinate Descent):** Алгоритм направленного поиска оптимума непрерывных параметров (пороги KWS, шаг фильтра AEC $\mu$, задержка $\tau_{\text{bulk}}$, полосы среза) по градиенту целевой функции `candidate_score` взамен слепой дискретной сетки (Grid Search). Доступен в Web UI, через REST API (`POST /api/v1/acoustics/optimize`) и MCP-инструмент.

## 2. Исходное состояние и ограничения

1. **Аппаратный захват:**
   - Интерфейс ALSA `hw:0,2` (`pcmC0D2c`, S32_LE @ 48 кГц, 8 каналов interleaved).
   - Каналы 0..3: 4 цифровых микрофона PDM MEMS.
   - Каналы 4..5: Неиспользуемые.
   - Каналы 6..7: Аппаратный digital loopback ЦАП/усилителя (TDMIN_B).
   - **Нулевой дрейф частоты:** Все 8 каналов поступают в одном DMA-буфере с тактовой точностью ($\Delta f = 0.000\text{ Гц}$).
2. **Вычислительные ресурсы:**
   - SoC Amlogic A113X (4 ядра Cortex-A53 @ 1.2 ГГц, ARM32v7/armhf/musl).
   - RAM: 236 МБ общего объема. Бюджет памяти на AEC: $\le 2\text{ МБ}$.
   - Бюджет процессора: $\le 5\text{–}8\%$ одного ядра CPU.
3. **Архитектурный выбор:**
   - **Post-Beamforming MDF (Multidelay Block Frequency Domain Filter):** Усреднение 4 микрофонов в 1 beamformed канал $\to$ 1 частотный адаптивный фильтр на 8 партиций ($K=8$, $N=256$, $L=2048$ сэмплов = 128 мс хвоста). Снижает вычислительную нагрузку в 4 раза по сравнению с 4-канальным фильтром без потери подавления.
   - Детектор одновременного разговора (Geigel DTD) для предотвращения разрушения коэффициентов во время речи пользователя.
   - Нелинейный постфильтр (RES Wiener) для подавления гармонических искажений базы (<180 Гц).

## 5. Откат и безопасность

- В `config.toml` предусмотрен флаг `[audio.aec] enabled = false`.
- При выключенном флаге `Decimator` работает в штатном режиме без вызова адаптивного фильтра.
- Скрипт `./scripts/deploy.sh` автоматически сохраняет резервную копию `mini-assistant.prev` на устройстве для мгновенного отката при сбое.
