## Контракт и архитектура

Пользователь открывает `/acoustics` из главной страницы, меняет параметры,
явно применяет их, видит подтверждённую ревизию аудиоцикла и сохранение.
Загрузка/импорт профиля только заполняют форму. Сброс формы не меняет устройство.
Существует возврат к фактически применённым значениям, экспорт без секретов.
Баллы DTW не называются процентами вероятности или плотностью фразы.

Рассмотрены два варианта: расширить прежнюю карточку на главном экране либо
выделить лёгкую страницу с общим backend. Выбрана отдельная страница того же
сервера: главная панель и обучение слова сохраняются, большие группы настроек
доступны на телефоне без перегрузки основного экрана.

Владелец параметров — `WakewordCalibrationConfig`; одна валидация для startup,
UI и hot reload. Сохранённая секция `[wakeword]` приоритетнее legacy env.
Все новые поля имеют совместимые defaults. Недопустимые значения отклоняются,
не заменяются молча другим значением. Модель и формат акустических эталонов
не меняются в рамках этой задачи.

`AcousticLab` хранит metadata snapshot и ограниченную очередь изменений.
Web POST с expected_revision сериализует изменения, атомарно сохраняет
конфигурацию и ожидает ACK от аудиоцикла. Saved/applied/pending/error различаются:
тайм-аут не считается применением. Пока предыдущая ревизия ожидает ACK,
новый POST отклоняется. Без работающего аудиоцикла нет ложного успеха.

Runtime применяет параметры между чанками с отменой незавершённого входного
хода и сбросом состояния детектора. Настройка wake-word disabled сохраняется
при reload. VAD не активирует idle сам по себе; manual/follow-up ждут речь.
Shadow mode считает детекции локально и не открывает облачные ходы или tools.
Источники звука/системные сервисы не перезапускаются при каждом движении ползунка.

## Реестр управления

- KWS: enabled, shadow mode, threshold, avg_threshold, min_scores, eager,
  все имеющиеся стратегии score_mode, DTW band size и score reference.
- Фильтры KWS: нормализация, min/max gain, optional RMS reference,
  полосовой фильтр, нижняя/верхняя границы.
- Речь: VAD base RMS, адаптивность, noise multiplier/offset,
  коэффициенты подъёма/спада noise floor, число кадров начала речи.
- Реплика: pre-roll, начальная тишина, конечная тишина, максимальная
  длительность, manual/follow-up window, echo tail, startup suppression.
- Акустический вход: программное усиление, optional earcon.
- Неизменяемый инвентарь: native/PCM форматы, канал микрофона,
  аппаратные/DSP зависимости и отсутствующие методы подавления шума.
  Не выдавать недоступную DSP-функцию за работающий переключатель.

GET `/api/v1/acoustics` возвращает schema controls, defaults, saved, applied,
revision и ограниченные числовые показатели runtime. Ни PCM, ни текст диалога,
ни credentials в API не попадают. Форма строится из той же schema, не из
отдельного списка диапазонов в JavaScript. POST требует JSON того же origin.

## Ограничения и откат

Задача делает настройку наблюдаемой; «идеальная сигнатура» ещё не подобрана.
Выбор профиля и его включение в defaults кода — следующий измеряемый шаг по
[плану надёжности](2026-11-22-wakeword-reliability.md), с отдельными positive/negative
записями. В этой задаче не записывать и не отправлять речь для подбора.
Сохранить текущие model/config, BUILD_INFO и предыдущий бинарник при deployment;
откат восстанавливает согласованный комплект, не только ползунки.
