## Акустическое ядро и варианты обращения

Одна активация «Штучка» используется для вопросов, умного дома и
будильников. В проверку фраз без паузы добавляем «Штучка, поставь
будильник на завтра в семь утра». Звонок и его остановка с корпуса
идут локальным путём. [Контракт вызова будильников](2026-11-05-local-alarms.md#общая-стратегия-вызова)

Первый кандидат определяет одно ядро **«Штучка»**. Для проверки используем:

1. «Штучка».
2. «Эй, Штучка».
3. «Слушай, Штучка».
4. «Штучка-интеллект».
5. Те же обращения сразу перед обычным вопросом.

В enrollment размечаем само «Штучка», сохраняя тихое начало/конец; полные фразы
нужны для проверки контекста. Matcher не понимает смысловых синонимов.
Смешивание четырёх целых разных фраз в один median-reference не считается
поддержкой aliases: `avg_features` и медиана могут отвергнуть совпадение
лишь с меньшинством шаблонов. Отдельные многословные детекторы — другая ветка.

Короткое слово может встретиться в обычном разговоре («эта штучка»). Для
акустического KWS это положительное наличие слова, а не доказательство
обращения. Если нужна активация только по «эй, Штучка», потребуется явная
политика адресного обращения и отдельная проверка, а не обещание по названию.

## Корпус: сначала 32 произнесения, а не 32 шаблона в модели

Это предложенный пилот, не обещание требуемой точности.

| Набор | Объём | Условия | Использование |
|---|---:|---|---|
| Enrollment pool A | 8 | Четыре формы по2, обычный голос, обычное положение | Кандидаты эталонов |
| Enrollment pool B | 8 | Те же формы, другое удобное расстояние/чуть тише | Кандидаты эталонов |
| Development | 8 | Отдельный блок; разные темпы, вопросы сразу после имени | Подбор сегментов/параметров |
| Unseen test | 8 | Отдельный блок после замораживания кандидата | Финальная пилотная проверка |

Из первых16 выбираем6–8 согласованных эталонов одного слова. Текущий runtime
принимает3–8 references; большой корпус не означает загрузку всех примеров
в Mini. Оставшиеся записи не используем как новые обучающие данные после
того, как называем их test. Старый «heldout.wav», уже многократно просмотренный
в прошлой отладке, теперь является development fixture, не unseen test.

У каждого клипа: ID, блок/условия, start/end слова, ожидаемое срабатывание.
Длинная запись — контейнер нескольких коротких примеров, не один template.
Не растягивать слово специально. Начальные1–2с и края окна не использовать
для обучения: у capture был измерен стартовый DC transient.

## Отрицательные примеры и фон

- Похожие слова: «штука», «шутка», «тучка», «точка», «уточка», «чуточку».
- Префиксы без имени: «эй», «слушай», «послушай».
- Вопросы/команды без имени: «сколько будет два плюс два», «какая погода»,
  «как дела», «включи свет», «выключи кондиционер» и обычная беседа.
- Неречевые события: кашель, хлопок, клавиатура, шаги, фоновая музыка/ТВ.
- Упоминания настоящего «Штучка» храним отдельно: для выбора политики
  адресного обращения, не подменяем ими акустические negative labels.

Первый набор —24 короткие отрицательные пробы плюс отдельные фоновые блоки.
Для предварительной приёмки автозапуска нужен длительный непрерывный фон,
например60мин, со счётчиком ложных активаций. Ноль на одном часе не доказывает
«никогда». Сброс детектора каждую минуту не эквивалентен непрерывному часу.
Текущий offline `test` ограничен60с; длительный stateful evaluator — незакрытая
задача перед этим испытанием.

Формат manifest (условные файлы/границы, не готовая разметка владельца):

```json
{
  "samples": [
    {"path": "session-a.wav", "start_ms": 2200, "end_ms": 3200},
    {"path": "session-a.wav", "start_ms": 6200, "end_ms": 7200},
    {"path": "session-b.wav", "start_ms": 2500, "end_ms": 3500}
  ]
}
```

Сегмент — mono16k PCM16,0.3–3с; исходный WAV — не более60с. Отмеченные границы
сохраняют полное слово. Auto-trim по самому сильному участку остаётся legacy
опцией старой команды, его результат не считается фонетической разметкой.

Timestamps evaluator обозначают время конца обработанного кадра. Это не
истинный конец слова и не измеренная задержка без сопоставления с labels.
Hits в отдельном2с synthetic tail показываются отдельно. Последний input frame
тоже может быть дополнен нулями; его offset относится к input bucket и может
оказаться менее чем на30мс позже реального EOF. Размер padding указан в JSON.

## Как собирать записи

Перед захватом — свежая проверка модели/прошивки/питания/доступа и paused voice.
Отдельно объявить начало/конец согласованного окна и назначение данных.
Предлагаемый формат — до60с на блок, с запасом на чтение инструкции; не
повторять прежние слишком короткие окна, в которых значительную часть съела
задержка чата. Не делать вывод о пропуске, если слово сказано после deadline.

Идём по тому же тракту Mini до MINI_MIC_GAIN: capture8ch48kS32 → наш downmix/
decimator → mono16kPCM16. Исходные mono WAV и manifests остаются приватными,
не отправляются LLM и не попадают в Git. Согласованный poolA60с уже записан приватно; владелец подтвердил8обращений
по порядку. Контрольный negativeA60с записан отдельно. Это первые восемь из 32
запланированных положительных примеров и один контрольный блок.
Cloud/HA/output выключены при сборе корпуса. Устройство/маршрутизатор/SSH
и постоянный supervisor в этой offline-доработке не изменяются.

Отдельный блок `poolBContext` содержит по два естественных «Слушай, Штучка»
и «Штучка-интеллект». Он использован для разработки отдельных эталонов
полных обращений. Совпадения на повторе из того же сеанса не перенеслись
на исторический ретейк. Этот блок относится к train/dev. Для следующего
кандидата сохраняем раздельные сеансы обучения, подбора и приёмки.
[Измерения](../experiments/2026-11-05-wakeword-corpus-calibration.md).

## Голос и характер ответа

В Gemini Live доступен выбор предустановленного голоса через session
speechConfig; в нашем коде уже используется `assistant.voice`. Голоса можно
прослушать в [AI Studio Live](https://aistudio.google.com/app/live-api).
Подтверждение: [Google Live guide](https://aistudio.google.com/docs/live-api/capabilities#change-voice-and-language).

Тембр и характер разделяем: голос — voiceName, стиль/краткость/юмор — отдельная
инструкция. Настройки характера не меняют локальные разрешения mic/tools.
Удобный переключатель профилей ещё не реализован; текущий клиент передаёт
голос при создании сессии, выбор не равен смене модели или обучению.

Если понадобится отдельный TTS, можно сравнить:

- [Google TTS и каталог/прослушивание](https://aistudio.google.com/docs/speech-generation).
  Это отдельный API; поддержку его дополнительных voice IDs в Live не предполагаем.
- [Piper samples](https://rhasspy.github.io/piper-samples/) — выбрать Russian/ru_RU.
- [Русские готовые модели Piper](https://huggingface.co/rhasspy/piper-voices/tree/main/ru/ru_RU):
  denis,dmitri,irina,ruslan. Для голосов есть отдельные MODEL_CARD;
  [описание формата моделей](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/VOICES.md).

Это готовые голоса/модели, а не обязательные датасеты для обучения с нуля.
Тест TTS не запускался. Piper/ONNX на нашей ARM32 Mini ещё не принят по RAM,
скорости, ABI и требованию нашего Rust runtime; Pi остаётся только HA.
Чужой dataset не подставляется в Gemini Live вместо встроенного голоса.

## После активации

1. Один вопрос → один полный ответ, затем несколько реплик без самозапуска.
2. Проверить timeout/cancel/reconnect и тишину после ответа.
3. На выключенном питании восстановить динамик, затем согласовать тихий
   акустический тест; проверить drain/echo. Сейчас слышимость не доказывается.
4. Вернуть разрешённую HA-интеграцию и отдельно проверить одно действие.
5. Выбрать голос/характер, затем музыка/Spotify и последующие hardware gates.

Gemini остаётся текущим прототипом, не окончательным выбором провайдера.
Полная замена vendor audio/ОС — отдельные пункты целевой архитектуры.

## Откат и критерии перехода

Offline CLI не перезаписывает существующие model files; candidates имеют
новые имена и остаются приватными. Device rollout и снятие voice.paused
не являются частью этой доработки. Непрошедший кандидат не заменяет baseline.
Старая команда и fixture-контракты сохраняются.

Нужны timestamps/labels, положительные/отрицательные результаты и ресурсы
на Mini. Количество файлов и успешная сборка сами по себе не означают
надёжную активацию. Приёмка корпуса и полного runtime пока открыты.

эталоны полного слова «Штучка» внутри связных обращений. Оценку проводим на
отдельной записи и длинном фоне. Постоянный режим остаётся на паузе.
