# План: Устранение задержек, поддержка любых городов, точные параметры ветра и голосовое прерывание (Barge-in / Stop)

- Статус: done
- Дата: 2026-11-04
- Репозиторий и владелец: `mini-assistant/`, root workspace

## Задача и критерии готовности

По итогам живого тестирования пользователем выявлены проблемы взаимодействия:
1. **Задержка ответа:** Ассистент долго молчал после окончания фразы пользователя (~3.3 с суммарно). Критерий: уменьшить silence timeout с 1800 мс до 700 мс (`MINI_SILENCE_TIMEOUT_MS`), сократив ожидание более чем на 1 секунду. (ВЫПОЛНЕНО)
2. **Ограниченность локаций погоды:** Поддерживались только 3 города (Батуми, Тбилиси, Цихисдзири). Критерий: подключить динамический Open-Meteo Geocoding API (`https://geocoding-api.open-meteo.com/v1/search`), позволяющий запрашивать погоду для любых городов мира (Москва, Париж, Кутаиси и т.д.) с кэшированием в памяти. (ВЫПОЛНЕНО)
3. **Неточные ответы по погоде ("всё хорошо", "ветер не сильный"):** Модель заменяла точные метрики качественными оценками из-за директивы о "лаконичном/ленивом" стиле. Критерий: в системном промпте жестко зафиксировать обязательное указание точных чисел: скорость ветра в м/с (из `wind_speed_ms`), температура в градусах, влажность в процентах; запретить качественные отговорки. (ВЫПОЛНЕНО)
4. **Ассистент не останавливается (отсутствие Barge-in):** Во время воспроизведения микрофонный тракт полностью отбрасывался (`continue`), из-за чего станция была «глухой» во время речи и не реагировала на команды «стоп» / «хватит». Критерий: реализовать распознавание речи пользователя поверх звука динамика по порогу `barge_in_threshold` (40.0 RMS) с немедленным убийством процесса воспроизведения (`playback.interrupt()`), сбросом очереди и обработкой команд остановки в системном промпте. (ВЫПОЛНЕНО)
5. **Команда кондиционера:** Гарантировать безусловный вызов `control_home_device` при командах включения/выключения кондиционера, даже если в кэше сущностей устройство отмечено как `unavailable`. (ВЫПОЛНЕНО)
