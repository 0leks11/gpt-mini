# План: Интеграция официального движка Spotify Soloist (ARM32) на GPT Mini

- **Статус:** draft (согласование с пользователем)
- **Дата:** 08.11.2026, Asia/Tbilisi
- **Репозитории:** `gpt-mini` (документация и архитектура), `mini-assistant` (Rust-реализация)
- **Устройство:** Яндекс Станция Mini 1 (`GPT Mini` / `gpt-mini`, `192.168.1.110:2222`)

---

## 1. Задача и критерии готовности

### Главная цель
Обеспечить гарантированное, стабильное и физическое воспроизведение музыки из Spotify через встроенный динамик станции **`GPT Mini`** по подписке пользователя (Spotify Premium Individual) с возможностью управления как из приложений Spotify (телефон, компьютер), так и голосом («Штучка, включи музыку», «Штучка, стоп», «Громче/тише»).

### Наблюдаемые критерии готовности
1. **Обнаружение в сети (Spotify Connect):** В официальном клиенте Spotify на смартфоне и ноутбуке колонка отображается под именем **`GPT Mini`** (тип: Speaker) и мгновенно подключается.
2. **Физический звук без ошибок Keymaster:** При запуске трека (например, *Tame Impala — Currents*) звук воспроизводится из динамика станции (`hw:0,0`). В логах отсутствуют ошибки `error audio key 0 1` (AES-ключи дешифруются официальным DRM-движком).
3. **Управление и Barge-in (голосовой арбитраж):** При фразе «Штучка» или срабатывании детектора голоса `mini-assistant` отправляет команду паузы через локальный WebSocket (`127.0.0.1:9090`), музыка ставится на чистую паузу без срыва трека, ассистент отвечает голосом, затем воспроизведение возобновляется.
4. **Ресурсный бюджет:** Soloist + compat-runtime + `mini-assistant` суммарно укладываются в лимит оперативной памяти (менее 60 МБ RSS при свободных 146 МБ) и дискового пространства (до 36 МБ при свободных 49.9 МБ в `/data`).
5. **Безопасность системы:** Базовая прошивка и системные библиотеки Mini (`glibc 2.23`) не модифицируются и не заменяются. Никаких рисков превращения станции в кирпич. Кабель к Mac не требуется (все операции выполняются по воздуху через SSH).

## 2. Исходное состояние и архитектурный анализ

### Причина отказа от librespot
- Эксперимент от 08.11.2026 доказал: даже после 1 часа 10 минут полного радиомолчания и применения патчей rate-limiting (PR #1844, PR #1853), первый же запрос на воспроизведение завершился отказом:
  ```text
  [ERROR librespot_core::audio_key] error audio key 0 1
  [WARN  librespot_playback::player] Unable to load key, continuing without decryption: Service unavailable { audio key error 0x0001 }
  ```
- Серверы Spotify Keymaster на стороне инфраструктуры Spotify не выдают AES-ключи дешифрования открытому коду `librespot` для свежих когорт аккаунтов. Это делает невозможным использование неофициальных реверс-инженерных плееров.

### Архитектура с официальным Spotify Soloist
`Spotify Soloist` — официальный легковесный headless-клиент, выпущенный Spotify (август 2026) специально для DIY-устройств и умных колонок на ARM32/ARM64.
- Он содержит проприетарное официальное ядро Spotify Connect, признаваемое серверами Keymaster без блокировок.
- Управляется через встроенный локальный WebSocket сервер (`--ws 127.0.0.1:9090`) по JSON-RPC.
- Предоставляет CLI-утилиту управления `soloist ctl`.

## 3. Этапы и пошаговый план работ

### Фаза 1. Подготовка авторизации и compat-пакета (на Mac)
1. **Получение персонального Soloist API Key:**
   - Пользователь логинится на [developer.spotify.com](https://developer.spotify.com) под своим активным Premium-аккаунтом.
   - В разделе *Spotify Soloist API Key* нажимает кнопку генерации ключа (`spak_...`).
   - Ключ сохраняется в локальный защищенный файл конфигурации (не попадает в Git!).
   - *Важно:* Это персональный токен пользователя (User Identity) в рамках его потребительской подписки без платной тарификации.
2. **Сборка изолированного бандла библиотек `glibc-compat` (ARM32 armhf):**
   - Скачивание официальных armhf deb-пакетов Ubuntu Ports (Noble 24.04):
     - `libc6_2.39-0ubuntu8_armhf.deb` (предоставляет `ld-linux-armhf.so.3`, `libc.so.6`, `libm.so.6`, `libpthread.so.0`, `librt.so.1`, `libdl.so.2`)
     - `libatomic1_14-20240412-0ubuntu1_armhf.deb` (`libatomic.so.1`)
     - `apulse_0.1.14-1_armhf.deb` (мост `libpulse.so.0` в ALSA)
     - `libasound2` и `libglib2.0` (минимальные рантайм-зависимости для apulse)
   - Распаковка во временную структуру каталогов: `bundle/lib/`, `bundle/glibc/`.
   - Проверка зависимостей утилитой `readelf`/`objdump` на Mac.

### Фаза 2. Изолированное тестирование в RAM (`/tmp`) на GPT Mini
1. **Развертывание в `/tmp/soloist-test/`:**
   - На станции в `/tmp` доступно 117.4 МБ RAM.
   - Передача бандла на устройство через потоковый SSH:
     `tar -czf - soloist bundle | ssh -p 2222 root@192.168.1.110 "tar -xzf - -C /tmp/soloist-test"`
2. **Smoke-тест исполнения бинарника:**
   - Запуск через изолированный динамический компоновщик:
     ```bash
     /tmp/soloist-test/glibc/ld-linux-armhf.so.3 \
       --library-path /tmp/soloist-test/glibc:/tmp/soloist-test/lib \
       /tmp/soloist-test/soloist --version
     ```
   - Ожидаемый результат: Soloist запускается и выводит версию `v1.3.10`.
3. **Первичное сопряжение и проверка аудио:**
   - Запуск демона с полученным ключом:
     ```bash
     APULSE_PLAYBACK_DEVICE="hw:0,0" \
     /tmp/soloist-test/glibc/ld-linux-armhf.so.3 \
       --library-path /tmp/soloist-test/glibc:/tmp/soloist-test/lib:/tmp/soloist-test/lib/apulse \
       /tmp/soloist-test/soloist \
       -n "GPT Mini" \
       -k "$SOLOIST_API_KEY" \
       -w 127.0.0.1:9090 \
       -v
     ```
   - Проверка обнаружения в Spotify на Mac и телефоне.
   - Запуск трека: подтверждение дешифрования без ошибок `0x0001` и физического звучания динамика.

### Фаза 3. Интеграция в Rust-стек `mini-assistant`
1. **Реализация `SoloistController` в `mini-assistant`:**
   - Модуль `mini-assistant/src/spotify/soloist.rs`:
     - Подключение к WebSocket `ws://127.0.0.1:9090`.
     - Парсинг JSON-событий состояния (Track Info, Playback State, Volume).
     - Отправка команд: `pause`, `play`, `next`, `previous`, `set_volume`.
2. **Арбитраж звука (Barge-in / Voice priority):**
   - При обнаружении wake-word («Штучка») или срабатывании VAD:
     - Вызов `soloist.pause()`.
     - Ожидание завершения голосового ответа ассистента.
     - Вызов `soloist.play()` для плавного продолжения музыки.
3. **Обновление веб-дашборда на порту 8080:**
   - Отображение статуса Soloist, текущего трека и обложки на странице `http://192.168.1.110:8080`.

### Фаза 4. Долговременная установка на Flash (`/data`)
1. **Перенос в постоянный каталог:**
   - Размещение в `/data/opt/mini-assistant/soloist-env/` (требуется ~35 МБ из 49.9 МБ свободных).
   - Создание скрипта-обертки `/data/opt/mini-assistant/soloist-run.sh`.
2. **Интеграция в супервизор:**
   - Обновление `run-supervisor.sh` для автоматического старта `soloist-run.sh` при загрузке станции.
3. **Комплексная проверка после перезагрузки:**
   - Выполнение `reboot` на станции `GPT Mini`.
   - Проверка холодного старта: ассистент поднимается, Soloist доступен в Spotify Connect через 15 секунд после подачи питания.

## 5. Откат и безопасность

1. **Безопасность системы:**
   - Ни один системный файл в `/`, `/lib`, `/usr/lib` или `/system` не затрагивается.
   - Всё окружение Soloist изолировано внутри `/tmp/` (на этапе тестов) или `/data/opt/mini-assistant/soloist-env/` (на этапе продакшена).
2. **План отката (Rollback):**
   - В любой момент окружение Soloist удаляется одной командой: `rm -rf /data/opt/mini-assistant/soloist-env`.
   - Система возвращается в исходное состояние до проведения эксперимента.
3. **Открытые вопросы:**
   - Получение пользователем Soloist API Key на `developer.spotify.com`.
   - Точная настройка задержки (latency) и буферизации ALSA через `apulse` для исключения щелчков звука.
