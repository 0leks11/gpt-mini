# Wi-Fi Captive Portal и управление Spotify через Web API

- Статус — draft (согласовано архитектурное решение; разработка тестов и контракта).
- Дата — 07.11.2026, Asia/Tbilisi.
- Репозитории — план в `gpt-mini`, реализация в `mini-assistant`.

## Задача и критерии готовности

1. **Бесшовный онбординг без установки приложений (Zero-Install Wi-Fi):**
   - Пользователь зажимает физическую кнопку Mute на корпусе Mini на 5 секунд.
   - Станция издает звуковой сигнал и переходит в режим настройки SoftAP: сеть `Station-Mini-Setup` (открытая, без пароля).
   - Пользователь выбирает эту сеть на iPhone, Android, Mac или ПК.
   - Операционная система **автоматически открывает всплывающее окно (Captive Portal)** без ввода IP-адресов и без использования Bluetooth.
   - В окне отображается список найденных сетей Wi-Fi и поле ввода пароля.
   - После подтверждения станция подключается к домашнему Wi-Fi, гасит временную точку доступа и подтверждает подключение голосом/звуком.
   - При ошибке ввода пароля или таймауте (20 с) станция не зависает и возвращает точку доступа с сообщением об ошибке. Прежняя рабочая сеть сохраняется.

2. **Управление Spotify через официальный Web API на чистом Rust:**
   - Модуль `mini-assistant/src/spotify/web_api.rs` на базе встроенного `reqwest` (TLS `rustls-tls-webpki-roots`) без новых тяжелых зависимостей.
   - Команды плеера: `play`, `pause`, `next`, `previous`, `set_volume`, `get_state`, `search`.
   - Поддержка OAuth 2.0 PKCE и фонового обновления `refresh_token` при истечении срока действия.

3. **Мгновенный локальный отклик на голосовые команды управления (< 80 мс):**
   - Команды «Штучка, пауза / стоп / дальше / тише / громче» перехватываются локальным фильтром интентов (`src/interaction.rs`) сразу после распознавания.
   - Команда уходит напрямую в Spotify Web API без ожидания ответа LLM и без задержки 2–4 секунды.

4. **Аудио-тракт A2DP Sink:**
   - Воспроизведение официального аудиопотока Spotify со смартфона/ноутбука на динамик Mini через Bluetooth A2DP, защищенное от проблем с DRM и `AUDIO_KEY_FAILED`.

## Архитектура и сетевые протоколы

```text
  [ Пользователь с iPhone / Android ]
                 │
                 │ 1. Зажимает Mute (5 сек) → Mini включает SoftAP: "Station-Mini-Setup"
                 │ 2. Выбирает сеть Wi-Fi "Station-Mini-Setup"
                 ▼
  ┌────────────────────────────────────────────────────────────────────────┐
  │ ЯНДЕКС СТАНЦИЯ MINI 1 (Режим настройки SoftAP: IP 192.168.4.1)         │
  │                                                                        │
  │  [ DNS Captive Responder (UDP 53) ]                                    │
  │  Перехватывает любые запросы (*.apple.com, connectivitycheck.*)        │
  │  и возвращает 192.168.4.1                                              │
  │                                                                        │
  │  [ Embedded Web Server (TCP 80) ]                                      │
  │  Отвечает на пробы ОС:                                                 │
  │   - iOS:     GET /hotspot-detect.html       -> 200 OK (HTML портал)    │
  │   - Android: GET /generate_204, /gen_204    -> 302 Redirect на /       │
  │   - Windows: GET /connecttest.txt, /ncsi    -> 302 Redirect на /       │
  │   - Любой:   GET /                          -> 200 OK (HTML страница)  │
  │                                                                        │
  │  [ API Конфигурации (POST /api/connect) ]                              │
  │  Принимает SSID и пароль, безопасно настраивает wpa_supplicant         │
  └────────────────────────────────────────────────────────────────────────┘
                 │
                 │ 3. Ввод пароля домашней сети → Станция получает IP
                 ▼
  ┌────────────────────────────────────────────────────────────────────────┐
  │ ЯНДЕКС СТАНЦИЯ MINI 1 (Штатный режим домашней сети: 192.168.1.xxx)     │
  │                                                                        │
  │  [ Локальный Web UI & Spotify Setup (порт 8080) ]                      │
  │  Доступен по адресу http://mini.local:8080 или http://192.168.1.xxx     │
  │  Кнопка "Привязать Spotify" (OAuth PKCE) для получения refresh_token   │
  │                                                                        │
  │  [ SpotifyApiClient (Rust, reqwest) ]                                  │
  │  Прямое управление воспроизведением через api.spotify.com              │
  │                                                                        │
  │  [ Fast Intent Gate (< 50 мс) ]                                        │
  │  «пауза», «стоп», «дальше» → мгновенный вызов Spotify Web API          │
  └────────────────────────────────────────────────────────────────────────┘
```

## План реализации по шагам

### Этап 1. Модуль Captive Portal и DNS-перехватчик (`mini-assistant/src/wifi/`)
1. **Легковесный DNS-сервер (`src/wifi/dns.rs`):**
   - Слушает UDP `192.168.4.1:53`.
   - Любой запрос типа `A` (IPv4) парсится минимальным no-alloc декодером и возвращает ответ: `192.168.4.1`.
   - Bounded буферы (512 байт), защита от флуда.
2. **Встроенный HTTP-сервер портала (`src/wifi/portal.rs`):**
   - Чистый Rust на базе `tokio::net::TcpListener` без тяжелых фреймворков.
   - Обработка пробников:
     - `/hotspot-detect.html` (Apple iOS / macOS);
     - `/generate_204`, `/gen_204` (Android);
     - `/connecttest.txt`, `/ncsi.txt` (Windows);
     - `/api/scan` — возврат JSON со списком доступных сетей;
     - `/api/connect` — прием `{ "ssid": "...", "psk": "..." }`.
   - Встроенный статический HTML/CSS/JS (минимальный размер < 8 КБ, адаптивная мобильная верстка, без внешних CDN).
3. **Безопасная настройка Wi-Fi (`src/wifi/wpa.rs`):**
   - Передача пароля через stdin утилиты `wpa_cli` (исключает утечку через аргументы процесса в `/proc/PID/cmdline` и `ps`).
   - Использование `wpa_passphrase` и атомарная запись конфига с правами `0600`.
   - Проверка статуса подключения (`COMPLETED`) и получение адреса через DHCP.
   - Надежный откат при неудаче (возврат к точке доступа).

### Этап 2. Клиент Spotify Web API на чистом Rust (`mini-assistant/src/spotify/web_api.rs`)
1. **Структура `SpotifyApiClient`:**
   - Поля: `client_id`, `refresh_token`, кэшированный `access_token`, время истечения `expires_at`.
   - Автоматическое обновление токена через `https://accounts.spotify.com/api/token` при истечении срока или получении HTTP 401.
2. **Методы управления плеером:**
   - `pause()` — `PUT /v1/me/player/pause`
   - `play()` / `resume()` — `PUT /v1/me/player/play`
   - `next()` — `POST /v1/me/player/next`
   - `previous()` — `POST /v1/me/player/previous`
   - `set_volume(pct)` — `PUT /v1/me/player/volume?volume_percent={pct}`
   - `search_and_play(query)` — поиск трека/альбома и запуск.
3. **Тестирование:**
   - Мок-тесты на loopback-сервере для проверки всех ответов (204 No Content, 401 Token Expired, 403 Forbidden).

### Этап 3. Быстрый перехват команд управления (Fast Intent Gate)
1. **Интеграция в `src/interaction.rs`:**
   - Добавление детерминированного сопоставления шаблонов для команд управления воспроизведением.
   - При совпадении команды плеер реагирует мгновенно (< 50 мс), не отправляя аудио в Gemini/OpenAI.
   - Опциональный звуковой отклик (короткий клик/бип).

### Этап 4. Веб-интерфейс настройки в локальной сети
1. Легковесный сервер на порту `8080`, доступный после подключения к домашней сети (`http://mini.local:8080`).
2. Интерфейс привязки Spotify через OAuth PKCE.
3. Отображение статуса станции, уровня сигнала Wi-Fi и версии прошивки.

## План тестов (Проверки и доказательства)

### 1. Модульные тесты (Unit tests, выполняются на хосте Mac):
* `test_dns_responder_answers_a_record`: Отправка синтетического UDP-запроса `hotspot-detect.html` на тестовый порт DNS-сервера, проверка получения A-записи с адресом `192.168.4.1`.
* `test_captive_portal_routes`: Проверка ответов HTTP-сервера:
  - `GET /hotspot-detect.html` -> 200 OK + HTML;
  - `GET /generate_204` -> 302 Redirect;
  - `GET /connecttest.txt` -> 302 Redirect.
* `test_wpa_credentials_sanitization`: Проверка экранирования спецсимволов в SSID и пароле (пробелы, кавычки, управляющие символы).
* `test_spotify_token_refresh`: Мок-сервер возвращает новый `access_token` при запросе обновления.
* `test_spotify_player_commands`: Проверка корректности HTTP-заголовков (`Authorization: Bearer ...`) и тела запроса для `play`, `pause`, `volume`.
* `test_fast_intent_matching`: Проверка распознавания вариантов фраз («пауза», «останови музыку», «сделай тише», «громкость на 50»).

### 2. Интеграционные тесты на устройстве (Hardware verification):
* Зажатие кнопки Mute на 5 секунд → проверка появления сети `Station-Mini-Setup`.
* Подключение с iPhone → проверка автоматического всплытия окна Captive Portal.
* Ввод тестового пароля → проверка успешного получения DHCP-адреса и отключения SoftAP.
* Тест устойчивости к ошибкам: ввод заведомо неверного пароля → проверка того, что точка доступа не «окирпичивается» и возвращает сообщение об ошибке.
* Проверка команд Spotify: запуск музыки на телефоне/Mac, голосовая команда «Штучка, пауза» → замер задержки до остановки воспроизведения.

## Откат и безопасность

* **Безопасность учетных данных:** Пароли Wi-Fi и токен Spotify никогда не логируются, не передаются аргументами командной строки и сохраняются только в защищенном конфигурационном файле с правами `0600`.
* **Резервная копия сетевой конфигурации:** Перед переключением в SoftAP текущий рабочий файл `wpa_supplicant.conf` копируется во временный `.bak`. При неудачном онбординге конфигурация автоматически восстанавливается.
* **Штатные функции:** Сервисы Яндекса и ALSA-тракт не модифицируются деструктивно. Все изменения изолированы внутри нашего Rust-бинарника.
