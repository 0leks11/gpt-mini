# Инженерное руководство: Интеграция Spotify на Linux (Embedded/Headless) и настройка Spotify Developer Dashboard

Данный документ содержит исчерпывающее техническое руководство по интеграции аккаунта и сервисов **Spotify** на встраиваемых и headless Linux-системах (ARM32/ARM64/x86_64, Яндекс Станция GPT Mini, Raspberry Pi, Home Assistant хосты) и правильной конфигурации **Spotify Developer Dashboard**.

В руководстве строго разграничены **критически необходимые** настройки от **устаревших, бесполезных и вводящих в заблуждение** опций.

---

## 1. Архитектура воспроизведения на Headless Linux

### Проблема DRM и блокировки неофициальных клиентов (Keymaster Error 0x0001)
Исторически для Linux использовались open-source реверс-инженерные демоны (`librespot`, `raspotify`, `spotifyd`), подключающиеся к серверам Spotify по протоколам Shannon/Mercury.

**Современная реальность:**
- Потоки Spotify зашифрованы алгоритмом AES-128 (Ogg Vorbis / AAC).
- Ключи дешифрования выдаются серверами Keymaster (`spclient.wg.spotify.com`).
- Начиная с когорт аккаунтов 2024–2026 годов инфраструктура Spotify блокирует выдачу ключей клиентам без официального бинарного ядра DRM:
  ```text
  [ERROR librespot_core::audio_key] error audio key 0 1
  [WARN  librespot_playback::player] Unable to load key: Service unavailable { audio key error 0x0001 }
  ```
- Попытки использовать `librespot` приводят к полной тишине и сбросу воспроизведения.

### Архитектурное решение: Spotify Soloist
Единственное надежное решение для воспроизведения музыки по подписке (Spotify Premium) на кастомных устройствах — официальный headless демон **Spotify Soloist** (или официальный Spotify Connect eSDK):
1. Содержит сертифицированное Spotify DRM-ядро, валидируемое Keymaster без ошибок `0x0001`.
2. Управляется по локальному протоколу WebSocket (`ws://127.0.0.1:9090`) через JSON-RPC.
3. Не требует графического интерфейса и браузерных движков.

### Аудио-тракт: ALSA vs PulseAudio vs apulse
На минималистичных встраиваемых Linux-системах (например, glibc 2.23 на A113X GPT Mini) отсутствует тяжелый PulseAudio демон.
- Для вывода звука используется **ALSA** напрямую (`hw:0,0` или программный микшер `dmix`).
- Если бинарник плеера скомпилирован под PulseAudio, применяется легковесная прослойка **`apulse`** (`libpulse.so.0` wrapper), транслирующая вызовы PulseAudio в стандартный ALSA PCM без оверхеда.
- Для совместимости новых бинарников (требующих glibc >= 2.34) со старыми хостовыми системами используется изолированный runtime-бандл (chroot или запуск через альтернативный ELF-загрузчик `/path/to/ld-linux-armhf.so.3 --library-path ...`).

## 2. Spotify Developer Dashboard: Что релевантно, а что мусор

При настройке приложения на [developer.spotify.com/dashboard](https://developer.spotify.com/dashboard) многие разработчики совершают фатальные ошибки, путая клиентские и серверные типы авторизации или пытаясь использовать неподходящие SDK.

### Сводная матрица параметров

| Параметр в Dashboard | Статус | Назначение и вердикт |
| :--- | :---: | :--- |
| **App Name & Description** | **ОБЯЗАТЕЛЬНО** | Произвольное имя приложения (например, `GPT Mini Assistant`). Отображается пользователю при входе. |
| **Client ID** | **КРИТИЧНО** | Публичный 32-значный идентификатор. Используется в запросах OAuth 2.0 PKCE и Web API. **Безопасен для открытого хранения на устройстве.** |
| **Client Secret** | **НЕ ИСПОЛЬЗОВАТЬ НА УСТРОЙСТВАХ** | Секретный ключ приложения. **НИКОГДА** не зашивать в прошивку, скрипты или открытый код Linux-устройства. Архитектура PKCE разработана специально для работы **БЕЗ** Client Secret. |
| **Redirect URIs** | **КРИТИЧНО** | Список разрешенных URL для возврата кода авторизации. Требуется **100% точное посимвольное совпадение**. |
| **APIs Used: Web API** | **КРИТИЧНО** | Обязательно отметить чекбокс **Web API**. Без него запросы к `/v1/me/*` будут отклоняться. |
| **APIs Used: Web Playback SDK** | **НЕ ПРИМЕНИМО** | **НЕ ВКЛЮЧАТЬ для Linux-демонов.** Web Playback SDK — это JavaScript библиотека исключительно для веб-браузеров с поддержкой Encrypted Media Extensions (EME Widevine). В headless ALSA/Node/Python не работает. |
| **APIs Used: Android / iOS SDK** | **НЕ ПРИМЕНИМО** | Относится только к мобильным приложениям, взаимодействующим со штатным приложением Spotify на телефоне. |
| **Users and Access (Development Mode)** | **КРИТИЧНО** | В режиме разработки (по умолчанию) вход разрешен **ТОЛЬКО** аккаунтам, чьи Email явно добавлены в этот список (до 25 пользователей). Если аккаунт не добавлен — ошибка 403. |
| **Request Quota Extension** | **МУСОР / НЕ ТРЕБУЕТСЯ** | Требуется только для публичных коммерческих продуктов с аудиторией > 25 пользователей. Для личного умного дома или колонки не трогать. |
| **Website / Terms / Privacy Policy** | **ДЕКОРАТИВНО** | Опциональные поля. Пустые значения никак не влияют на работу API и авторизацию. |
| **Webhooks** | **НЕ СУЩЕСТВУЮТ** | Spotify Developer Platform **не предоставляет** входящих вебхуков для событий плеера. Состояние плеера отслеживается либо через локальный WebSocket Soloist, либо периодическим опросом (polling). |

## 3. Требования к Redirect URIs

Spotify жестко валидирует Redirect URI. При несовпадении хотя бы одного символа или порта пользователь получает ошибку `INVALID_CLIENT: Invalid redirect URI`.

### Правильные шаблоны Redirect URIs:
1. **Для встроенного Web UI устройства в локальной сети:**
   - `http://192.168.1.110:8080/api/spotify/callback` (по IP-адресу станции)
   - `http://gpt-mini.local:8080/api/spotify/callback` (по локальному mDNS-домену)
2. **Для локального CLI-хелпера на компьютере разработчика:**
   - `http://127.0.0.1:8888/callback`
   - `http://localhost:8888/callback`

### ⚠️ Типичные ошибки конфигурации URI:
- **Wildcard (`*`) запрещены:** нельзя писать `http://192.168.1.*:8080/callback`.
- **Путаница с закрывающим слэшем:** `.../callback` и `.../callback/` — это два **разных** URI для Spotify. Если в запросе передается без слэша, в Dashboard должен быть прописан без слэша.
- **Проброс портов и белый IP НЕ нужны:** Редирект выполняет браузер пользователя на его телефоне/компьютере. Если телефон находится в той же домашней Wi-Fi сети, он успешно откроет локальный адрес `http://192.168.x.x:8080`.

## 4. Протокол авторизации: OAuth 2.0 PKCE

Для встраиваемых систем, IoT-устройств и CLI-утилит единственным безопасным стандартом является **OAuth 2.0 Authorization Code with PKCE (RFC 7636)**.

```text
 ┌──────────────┐         1. Generate verifier & challenge         ┌──────────────┐
 │              │ ───────────────────────────────────────────────> │              │
 │              │         2. Open auth URL in user browser         │   Spotify    │
 │   GPT Mini   │ ───────────────────────────────────────────────> │ Accounts API │
 │  Web Server  │                                                  │              │
 │  (port 8080) │ <─────────────────────────────────────────────── │              │
 │              │    3. Browser redirects with ?code=...&state=    └──────────────┘
 │              │                                                         │
 │              │         4. POST /api/token (code + verifier)            │
 │              │ ────────────────────────────────────────────────────────┘
 │              │    (NO Client Secret sent!)
 │              │ <───────────────────────────────────────────────────────┐
 │              │         5. Returns access_token + refresh_token         │
 └──────────────┘
```

### Генерация PKCE-параметров:
1. **`code_verifier`**: Случайная криптографически стойкая строка длиной от 43 до 128 символов (символы `[A-Z]`, `[a-z]`, `[0-9]`, `-`, `_`, `.`, `~`).
2. **`code_challenge`**: Вычисляется как:
   $$\text{code\_challenge} = \text{Base64UrlSafeNoPadding}(\text{SHA256}(\text{code\_verifier}))$$

### Минимально необходимый набор Scopes:
Для полноценного управления плеером, отображения статуса и работы Spotify Connect требуются следующие области доступа:
- `user-read-playback-state` — чтение состояния плеера, активного устройства, громкости.
- `user-modify-playback-state` — управление воспроизведением (play, pause, next, prev, volume, seek).
- `user-read-currently-playing` — метаданные текущего трека (название, артист, обложка).
- `streaming` — управление потоковым воспроизведением на устройствах Spotify Connect.
- `user-read-email` — чтение email для сверки с белым списком.
- `user-read-private` — страна и тип подписки пользователя (Free/Premium).

### Обмен кода на токен (HTTP POST):
Endpoint: `https://accounts.spotify.com/api/token`
Headers: `Content-Type: application/x-www-form-urlencoded`
Тело запроса:
```http
grant_type=authorization_code
&client_id=<YOUR_CLIENT_ID>
&code=<AUTH_CODE_FROM_CALLBACK>
&redirect_uri=<EXACT_REDIRECT_URI>
&code_verifier=<ORIGINAL_CODE_VERIFIER>
```

### Автоматическое обновление токена (Refresh Token):
Время жизни `access_token` составляет 3600 секунд (1 час). По истечении срока `access_token` обновляется запросом:
```http
POST https://accounts.spotify.com/api/token
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token
&client_id=<YOUR_CLIENT_ID>
&refresh_token=<STORED_REFRESH_TOKEN>
```
*Важно:* Сохранять `refresh_token` в энергонезависимой памяти устройства (например, `/data/spotify_token.json`) с правами `0600`. Файл должен быть добавлен в `.gitignore`.

## 5. Взаимодействие с голосовым ассистентом: Barge-in и Ducking

Когда на устройстве играет музыка и пользователь произносит слово вызова («Штучка»), возникает акустический конфликт:
1. Музыка из динамика попадает в микрофоны станции.
2. Голосовой движок не слышит последующий вопрос пользователя или транскрибирует слова песни.

### Архитектура приглушения звука (Music Ducking)
Вместо полной остановки музыки применяется плавное приглушение (Ducking):
1. **Событие Wake-word:** При срабатывании детектора ключевого слова голосовой демон отправляет команду в локальный WebSocket Soloist (`ws://127.0.0.1:9090`) или в Web API:
   - Сохраняется исходный уровень громкости (например, 80%).
   - Громкость мгновенно снижается до **15–20%**.
2. **Сессия диалога:** Пользователь спокойно формулирует команду ассистенту на фоне тихой музыки.
3. **Восстановление громкости:**
   - После того как ассистент закончил озвучивать ответ (TTS Complete), громкость возвращается к исходным 80%.
4. **Аварийный таймер (Watchdog Timer):**
   - Если сетевое соединение с облачной LLM разорвалось или сессия зависла, фоновый таймер (таймаут 8–10 секунд) гарантированно восстанавливает громкость музыки, исключая залипание на 20%.

## 6. Матрица диагностики и устранения неисправностей

| Симптом / Ошибка | Первопричина | Метод устранения |
| :--- | :--- | :--- |
| `INVALID_CLIENT: Invalid redirect URI` | Несовпадение адреса в запросе и в настройках Dashboard. | Проверить протокол (`http` vs `https`), IP, порт и отсутствие лишнего слэша на конце в Spotify Developer Dashboard. |
| `403 Forbidden: User not registered in Developer Dashboard` | Аккаунт пользователя отсутствует в списке тестировщиков. | Перейти в Dashboard -> *Settings* -> *Users and Access*, добавить email аккаунта Spotify. |
| `AUDIO_KEY_FAILED (0x0001)` в librespot/spotifyd | Сервер Keymaster заблокировал неофициальный DRM-клиент. | Использовать официальный headless демон **Spotify Soloist** вместо librespot. |
| `404 Not Found: Device not found` при вызовах Web API | Колонка не выбрана в качестве активного целевого устройства. | Выполнить `PUT /v1/me/player` с телом `{"device_ids": ["<DEVICE_ID>"], "play": true}` для трансфера воспроизведения на колонку. |
| `401 Unauthorized` при запросе к Web API | Истек срок действия `access_token` (1 час). | Выполнить запрос обновления токена через `grant_type=refresh_token`. |
| Soloist не запускается на старом Linux (`version GLIBC_2.34 not found`) | Версия glibc в хостовой системе устарела. | Использовать chroot-окружение или изолированный запуск через совместимый `ld-linux-armhf.so.3` с локальными библиотеками. |
