# Общий план GPT Mini: прогресс, качество и безопасность

## Будильники и общий вызов команд

Сейчас «Штучка» открывает одну голосовую реплику. Целевой сценарий — одно
обращение на диалог с ограниченным окном ответа после каждого уточнения.
При тишине или отмене Mini закрывает диалог. Изменение расписания проходит
через локальный черновик и подтверждение. Расписание хранится на Mini,
действия умного дома идут в HA на Pi, вопросы обрабатывает голосовой
провайдер. Для всех команд используется одно обращение.
[План голосового диалога](plans/2026-11-06-dialog-recovery.md)

получает отдельный приоритет звука, а голосовые команды используют общее
обращение. На Mini подтверждены слышимый звонок и остановка из CLI.
Остаются остановка с корпуса, проверка без WAN и холодный запуск с
проверкой часов. Улучшение KWS идёт отдельной задачей.

## 4. Оценка качества кода

**Сильные стороны:** небольшие модули, автоматизированные host-проверки, bounded
VQE parsing и negative tests, отделённые cloud/HA/audio интерфейсы, typed
generation в output queue, локальная HA policy, отсутствие shell execution
при чтении dotenv, pinned SSH identity.

**Основная слабость:** состояние живёт одновременно в atomic flags, reader,
worker, дочернем процессе и detached timers. Форматирование и unit-тесты
эти межпоточные контракты не доказывают. Нужны end-to-end fake-process tests,
контролируемые clock/transport/renderer и один supervisor состояния.
Line/branch coverage и актуальная база CVE зависимостей не проверялись;
число тестов не считать покрытием продукта. Воспроизводимость полного release
с native helper ещё предстоит обеспечить.

## 5. Подтверждённые замечания и необходимые исправления

### R1 — P1: приватные payload вновь попадают в INFO-логи

`src/gemini/live_client.rs:333–353,375–396`: raw frame preview, output transcript
и response text логируются. Preview может содержать также tool arguments и
base64 аудио. Fake WS отправил synthetic marker, который появился в логах.

- [ ] Удалить payload logging по умолчанию, оставить тип события/размер/код/время.
- [ ] Покрыть transcript, text, args, audio и ошибки тестом capture logs.
- [ ] Не ограничиваться INFO→DEBUG: проект включает debug для своего target.
- Приёмка: ни один synthetic private marker не попадает в стандартный лог.

### R2 — P1: VAD не обеспечивает активацию только по ключевому слову

`src/main.rs:193–223`, `src/wakeword/mod.rs:124–164`: достаточно громкая
посторонняя речь открывает gate. `wake_words` не участвуют в распознавании.
Один engine используется и для активации, и для продолжения речи.

- [ ] Разделить ActivationDetector/KWS и SpeechActivity/VAD.
- [ ] До готового KWS явно отделить демонстрационный VAD/open-mic режим.
- [ ] Для контролируемого режима предусмотреть явную ручную активацию;
  открытие по любой громкой речи не выдавать за защиту фона.
- [ ] Тесты: речь без слова → 0 cloud frames; слово → разрешённый вопрос;
  длинный вопрос после one-shot KWS не обрывается без повторения слова.
- [ ] Проверить mute/stop и ложные активации на музыке/фоновой речи.
- Приёмка: privacy gate подтверждён отрицательными сценариями, а не тихой комнатой.

### R3 — P1: старый END timer снимает защиту во время следующего ответа

`src/audio/playback.rs:171–186`: после END detached timer через 350 мс
без проверки child/generation пишет is_playing=false. В fake renderer тесте
следующий процесс ещё работал, а flag уже сбросился. Микрофон снова может
попасть в VAD во время собственного звука.

Дополнительно `live_client.rs:401–414` выдаёт END и на generationComplete,
и на turnComplete. Их нельзя считать двумя независимыми завершениями звука.
Текущий turn_counter увеличивается только при interruption: это cancellation
epoch, а не уникальный ID каждого обычного ответа. Одна проверка generation
в timer поэтому недостаточна для двух последовательных непрерванных ответов.

- [ ] Заменить fixed sleep настоящим drain/exit/report acknowledgment.
- [ ] Привязать завершение к конкретной session/turn/generation.
- [ ] Разделить response ID и cancellation epoch; завершение сделать
  идемпотентным, а physical drain подтверждать renderer.
- [ ] Не терять Child при замене; wait/reap и bounded cleanup для каждого child.
- [ ] Тесты: A END → B start; late completion A не меняет состояние B;
  slow drain, partial write, cancel, EOF и SIGINT под нагрузкой.
- Приёмка: никакой старый timer/child не меняет playback state нового ответа.

### R4 — P1: ожидание HA reply блокирует управление WS

`src/gemini/live_client.rs:429–445`: reader ожидает tool result и не читает
следующий interruption. Fake WS воспроизвёл задержку. DTO не обрабатывает
toolCallCancellation/goAway; успешный ping не заменяет их обработку.

- [ ] Вынести tools в отдельный dispatcher, продолжать чтение control events.
- [ ] Deadline/call-ID/cancellation registry; не выполнять ещё не начатое
  отменённое действие, не повторять неоднозначно выполненное автоматически.
- [ ] Для уже отправленного HA action честно различать accepted/unknown outcome.
- Приёмка: медленный fake HA не блокирует cancel; нет действия после отмены
  до dispatch и нет дублирования после reconnect.

### R5 — P2: отсутствие session supervision

`GeminiLiveClient` — пустой handle; обе WS tasks detached. EOF/error завершает
task, но main остаётся ждать Ctrl-C и может показывать старую readiness.

- [ ] Один supervisor: CONNECTING/READY/DEGRADED/STOPPED, cancel и join handles.
- [ ] Останавливать/ограничивать mic/output при потере backend; bounded reconnect.
- [ ] Тесты: remote close, network stall, rejected setup, goAway, process shutdown.
- Приёмка: потеря WS наблюдаема приложением; нет ложного состояния «активен».

### R6 — P1 release: helper не входит в доставляемый набор

`src/audio/playback.rs:29–67` предпочитает mini_pcm_sink, но deploy загружает
только Rust binary/config/env. Успех на уже подготовленной Mini не доказывает
установку на чистый экземпляр. Fallback может выбрать неработающий aplay/Mock.

- [ ] Versioned release manifest: Rust binary, native renderer, ABI/hash/limits.
- [ ] Доставлять helper либо явно проверять совместимый установленный asset.
- [ ] На Mini отсутствие рабочего renderer должно снимать readiness, не
  превращаться в молчаливый mock success.
- Приёмка: fresh-directory fixture воспроизводимо устанавливает полный набор.

### R7 — P2: deployment integrity/rollback ещё не обеспечены

`scripts/deploy.sh:147–163`: binary .new+rename улучшает замену одного файла,
но remoteSHA только печатается; config/env пишутся inplace. В fake с hash
из 64 нулей deployment всё равно завершился успешно. Fallback branch не покрыт
восемью обычными тестами, где fake which scp всегда успешен.

- [ ] Сравнивать local/remote hashes до активации каждого артефакта.
- [ ] Staging всего набора, permissions, backup и точечный rollback.
- [ ] Тесты: нет SCP, partial upload, wrong hash, chmod failure, helper missing.
- Приёмка: повреждённый/неполный набор не активируется и не получает success.

### R8 — P2: lab-limits native sink не согласованы с длинным ответом

Указанный в журнале helper с SHA256
`0ec76525ac1891a9cdf0864c900f0a54de7b2ebca9b6628a37b90fe523b31a58`
соответствует исследовательскому sink:
`MAX_FRAMES=480000` (10 с при 48 kHz), wall deadline 12 с. Rust не читает отчёт helper
и не учитывает эти пределы. Ответ длиннее лимита может обрезаться/перезапустить
renderer без корректного отражения ошибки. Статический контракт проверен
по `research/alice-mini-2019/lab/tools/mini_pcm_sink.c:31,197,221` и evidence.

- [ ] Принять явный runtime contract helper: duration/idle/queue/format/status.
- [ ] Читать bounded report/exit и отличать accepted от played/drained.
- [ ] Тесты со stand-in ALSA: речь 15/30/60 с, доставка с паузами, cancel.
- [ ] Изолировать все renderer unit tests: системный aplay не должен запускаться.
- Приёмка: длинный разрешённый ответ не теряет звук и не оставляет zombie/child.

## 6. Безопасность: что уже есть и что остаётся доказать

Уже полезны: key-only SSH/pinned host key; права каталогов/env; dotenv как
данные; HA allowlist/service/parameter guards; bounded JSON/timeouts;
отсутствие произвольного shell tool для модели. Известных credential-pattern
совпадений в проверенном индексе не найдено; это не гарантия отсутствия всех
секретов, персональных данных в логах или утечек во всей Git-истории.
HA allowlist ограничивает этот исполнитель; она не сужает сама по себе права
bearer token в Home Assistant. Права конкретного токена здесь не проверялись.

До приёмки нужны R1–R4, отсутствие фоновой отправки без согласованной активации,
проверка mute/stop, scoped egress Mini и доказательство отсутствия обращений
к Яндексу. Не расширять root-доступ/сеть как побочный эффект. Для будущего
непривилегированного процесса сначала проверить требования audio/IPC/файлов.

Периодический ping и живой PID не доказывают живую модельную сессию.
Один RSS или ровный участок не доказывает отсутствие утечек; кадры/с считаются
принятыми кадрами, а не автоматически 0% потерь без ожидаемого счётчика/sequence.

## 7. Очерёдность исполнения

| Этап | Что сделать | Критерий перехода |
|---|---|---|
| G0 — фиксация | Снимок, source hashes, условия, состояние Git | Понятно, какую версию и режим проверяем |
| G1 — приватность | R1; интерфейсы R2 и контролируемая ручная активация до KWS | Нет private logs/самовольной фоновой отправки в выбранном режиме |
| G2 — audio lifecycle | R3, R8; child lifecycle/ack; явный half/full-duplex выбор | Fake-process и длинные ответы проходят без старого звука/процессов |
| G3 — backend/tools | R4, R5; supervision/cancellation/dedup | EOF/slow HA/cancel/reconnect не дают скрытого действия или ложной readiness |
| G4 — release | R6, R7; полный manifest и rollback | Чистая установка/ошибки доставки/повторный запуск проверены |
| G5 — KWS на Mini | Кандидат+русский датасет+ARM32 build+реальные измерения | Согласованы false accepts/rejects, RSS/CPU/latency, privacy gate |
| G6 — контролируемый пользовательский прогон | Диалог, длинный ответ, стоп/mute, разрешённый HA, сеть пропала/вернулась | Воспроизводимый результат/cleanup; p50/p95 по репликам, peak RSS |
| G7 — функции продукта | Погода, OpenAI provider, Spotify, память/контекст, локальный intent | Отдельный контракт и tests для каждой интеграции |
| G8 — собственная ОС | Отдельная ветка BSP/kernel/rootfs/boot | Backup/recovery/driver gates L2–L4; исходная цель миграции ОС сохранена |

G1–G4 — ближайшая инженерная очередь. KWS-прототип можно исследовать параллельно,
но подключение не заменяет исправление lifecycle и tests. Типичный QA-прогон
не должен включать настоящее устройство или HA-сервис.

## 8. Поправки к доказательствам и документации

- WAKEWORD.md — проект, не результат benchmark. Числа RAM/CPU и гарантии
  «100% приватность/абсолютная надёжность» убрать до измерений.
- STATE хранит факты с источником: код/локальный тест/журнал владельца/живой опыт.
- Старые замечания spawn/cancel и нетегированной очереди не переносить как
  неизменённые: в текущем снимке появились post-spawn guard и typed queue.
  Новый подтверждённый дефект — END/drain lifecycle, а не прежняя гонка.
- Перед публикацией собрать осмысленные коммиты в обоих Git; нынешний HEAD
  приложения не содержит всей проверенной реализации. Не коммитить чужой diff.
- Следующий отчёт обновляет статусы R1–R8 с regression tests и evidence,
  а не только увеличивает число зелёных тестов.

Официальный контракт control events/сессий: [Gemini Live WebSocket API](https://ai.google.dev/api/live).
Там различаются generationComplete/turnComplete и предусмотрены cancellation
и goAway; текущий клиент должен обрабатывать их по роли, а не считать ping
доказательством бессрочной работоспособности.
