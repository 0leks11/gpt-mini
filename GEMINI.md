# Архитектурные принципы и контекст GPT Mini (Brownfield Ingestion)

## ⚠️ Главные принципы сохранения существующей системы
1. **Уважение к существующей архитектуре**: Не переименовывать существующие папки, документы (`docs/STATE.md`, `docs/plans/`, `docs/DEVELOPMENT_RULES.md`) и модули проекта.
2. **No Destructive Rewrites**: Запрещено переписывать существующие рабочие файлы целиком. Только хирургические точечные правки.
3. **Сохранение аппаратных интерфейсов**: Сверять любые подключения и шины с `docs/hardware_pins.md`, не менять назначенные I2C/UART/ALSA адреса.
4. **Контекст перед действием**: Сначала сверяться с существующими файлами проекта, `docs/STATE.md` и `docs/tasks/active_tasks.md`.
5. **Атомарные коммиты**: Любые новые изменения фиксировать в Git отдельными шагами с Conventional Commits.

## 🎯 Ключевые инварианты GPT Mini
- **Именование**: Устройство и репозиторий называются исключительно **`GPT Mini`** / **`gpt-mini`** во всех логах, интерфейсах, заголовках и документации.
- **Автономия пользователя (User Independence)**: Пользователь не должен зависеть от агента для бытовых настроек (выбор голоса, модели, слова вызова, цвета LED, Wi-Fi, перезагрузка). Все изменяемые параметры вынесены в Web UI / Telegram Mini App (`http://<ip>:8080/`) и управляются через `config.toml` с горячей перезагрузкой.
- **Авторизация по подписке (OAuth User Identity)**: Использовать исключительно OAuth-авторизацию по подписке (User Identity / Browser Login). Не подменять пользовательскую авторизацию сервисными платными API-ключами.
- **Полная автономность устройства**: Весь голосовой runtime (Gemini Live, Spotify Soloist, Rustpotter KWS, Web UI) исполняется локально на A113X GPT Mini. Вспомогательный Raspberry Pi обслуживает только Home Assistant.
- **Двухуровневый Git**: Корневой репозиторий управляет инфраструктурой, документацией и стендом; вложенный `mini-assistant/` является отдельным Rust-репозиторием со своей историей версий и тестами.
