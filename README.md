# GPT Mini — правила разработки и рабочее пространство

Цель — использовать оригинальное железо Mini 1 для собственного голосового
ассистента, диалога с выбранной моделью, Home Assistant и Spotify с полной
заменой ПО Яндекса. Наш Rust-стек исполняется на Mini; Pi обслуживает только HA.
Это целевое поведение, а не заявление о готовности системы.

## С чего начать

1. Прочитать [AGENTS.md](AGENTS.md), [текущее состояние](docs/STATE.md)
   и [общий план с текущим ревью](docs/GENERAL_PLAN.md).
   Обязательная граница архитектуры: [автономная Mini](docs/TARGET_ARCHITECTURE.md).
2. Работать по [workflow](docs/WORKFLOW.md).
3. Выбрать проверки по [матрице тестирования](docs/TESTING.md).
4. Перед коммитом пройти [ревью](docs/CODE_REVIEW.md).

План новой интеграции: [погода для Mini и Home Assistant](docs/plans/2026-11-03-weather-integration.md)
— провайдер, сохранённые места, голос, геолокация и сводки; пока draft.

## Два независимых репозитория

| Каталог | Назначение | Git |
|---|---|---|
| Корень `gpt-mini` | Общие правила, решения, шаблоны и проверки workflow | Этот репозиторий |
| `mini-assistant/` | Экспериментальное Rust-приложение и его CI | Собственный существующий репозиторий |
| `research/alice-mini-2019/` | Локальное исследование, C/Python-прототипы и evidence | Пока исключён из корневого Git |
| `.private/` | Приватные дампы, стенд и учётные данные | Никогда не добавлять |

Вложенный репозиторий сохранён вместе с его историей. Это не submodule.
Общие правила из корня доступны агенту в этом рабочем пространстве; при отдельном
клонировании приложения действуют его собственные `AGENTS.md` и `CONTRIBUTING.md`.
Перенос исследовательского архива в Git требует отдельного отбора и проверки.

## Проверки без оборудования

```sh
python3 scripts/check_workflow.py
python3 -B -m unittest discover -s tests -v
```

Проверка Markdown использует индекс Git; новые документы сначала добавляют
явным списком файлов. Проверка содержимого будущего коммита:

```sh
python3 scripts/check_workflow.py --staged
git diff --cached --check
git diff --cached --stat
```

После клонирования включить локальный pre-commit hook:

```sh
git config --local core.hooksPath .githooks
```

Hook проверяет будущий коммит: пути секретов, известные форматы ключей,
размер файлов и локальные ссылки Markdown. Это базовая защита от случайной
ошибки; ревью diff по-прежнему обязательно. Внешние URL и Markdown-якоря
проверка ссылок не проверяет. Проверки не подключаются к Mini,
Pi, Home Assistant или облачным API.
