# GPT Mini

Домашний проект по превращению старой Яндекс Станции Мини первого поколения (модель YNDX-0004, 2019 года) в полностью автономного голосового ассистента.

В этом проекте нет ничего инновационного или революционного: здесь не создаётся новый искусственный интеллект и не разрабатываются сложные алгоритмы. Главная цель была предельно простой и прикладной — **на 100% избавиться от архитектуры и софта Яндекса**, чтобы на оригинальном заводском железе работало **0% кода Яндекса** и 100% открытый самописный стек на Rust.

---

## Что это такое

Оригинальная Яндекс Станция Мини 1 работает на четырёхъядерном процессоре Amlogic A113X (Cortex-A53), но её штатный userspace собран под 32-битный ARM (`armhf`) с ядром Linux 4.9.68 и всего ~236 МБ оперативной памяти.

Вместо закрытых сервисов Яндекса (`maind`, `yio_audio`, проприетарные демоны телеметрии и VQE) на колонке теперь крутится единственный компактный сервис `mini-assistant`, написанный на чистом Rust.

Колонка полностью автономна: она не требует постоянного компьютера рядом, не зависит от сторонних серверов и связывается напрямую с нужными API:

- **Голосовые модели**: двусторонний аудиостриминг по WebSockets с минимальной задержкой через **Gemini Live API** (`models/gemini-3.8-live`) или **OpenAI Realtime** (`gpt-4o-realtime-preview`).
- **Захват звука**: прямой опрос 4 микрофонов через ALSA (`hw:0,2` PDM децимация в 16 кГц PCM16).
- **Слово активации (Wake word)**: локальное распознавание на базе Rustpotter KWS без отправки аудио в облако. Прямо в браузере доступен мастер записи собственного ключевого слова (например, *"штучка-интэлэкт"*).
- **Музыка**: локальный Spotify Connect (через Spotify Soloist / librespot) с пропорциональным приглушением громкости (ducking) при разговоре и мгновенной реакцией на голос.
- **Умный дом**: управление устройствами, светом и кондиционером через локальный Home Assistant REST API.
- **Датчик жестов**: опрос заводского ToF-сенсора ST VL53L0X для регулировки громкости движением руки над колонкой.
- **Панель управления**: легковесный локальный веб-интерфейс и Telegram Mini App на порту `8080` (выбор голоса, громкость, цвет LED-индикатора, обучение wake-word).

## Архитектура и структура репозитория

Проект организован в виде двух независимых уровней:
- **`gpt-mini`** (текущий репозиторий) — системная архитектура, документация, схемы, распиновки и регламенты деплоя.
- **[`mini-assistant`](https://github.com/0leks11/mini-assistant)** — исходный код встраиваемого Rust-демона, юнит-тесты и скрипты сборки.

```text
gpt-mini/
├── mini-assistant/          # Исходный код Rust-демона (https://github.com/0leks11/mini-assistant)
│   ├── src/                 # Модули: audio, gemini, openai, wakeword, spotify, ha, web
│   ├── scripts/             # Скрипты сборки (build.sh), деплоя (deploy.sh) и верификации
│   ├── tests/               # 210+ юнит-тестов
│   ├── Cargo.toml           # Манифест Rust (target: armv7-unknown-linux-musleabihf)
│   └── config.example.toml  # Пример конфигурации
├── docs/                    # Документация, распиновки и реверс-инжиниринг
│   ├── hardware_pins.md     # Распиновка разъёмов, шины I2C, GPIO, ALSA адреса
│   ├── TARGET_ARCHITECTURE.md# Целевая архитектура и границы проекта
│   ├── DEVELOPMENT_RULES.md # Регламент релизов и проверок на железе
│   └── STATE.md             # Журнал разработки и проверенные гипотезы
├── scripts/                 # Локальные утилиты для проверки workflow
└── README.md                # Это описание
```

Подробные аппаратные характеристики, схема подключения шин I2C/UART и адреса аудиоустройств зафиксированы в [docs/hardware_pins.md](docs/hardware_pins.md).

## Сборка и установка

### 0. Клонирование репозиториев
```sh
git clone https://github.com/0leks11/gpt-mini.git
cd gpt-mini
git clone https://github.com/0leks11/mini-assistant.git
```

### 1. Подготовка конфигурации
Скопируйте примеры файлов конфигурации:

```sh
cd mini-assistant
cp .env.example .env
cp config.example.toml config.toml
```

В `.env` укажите ваш API-ключ Gemini (`GEMINI_API_KEY`) или OpenAI (`OPENAI_API_KEY`). Секреты и токены изолированы и никогда не попадают в git.

### 2. Кросс-компиляция
Для сборки под 32-битный ARM musl используется готовый Docker-контейнер:

```sh
cd mini-assistant
./scripts/build.sh
```

В результате создаётся статический бинарник `mini-assistant`, не требующий внешних разделяемых библиотек на устройстве.

### 3. Деплой на колонку
Для заливки бинарника и скриптов инициализации по SSH:

```sh
MINI_HOST=192.168.1.110 MINI_SSH_KEY=~/.ssh/id_ed25519 ./scripts/deploy.sh
```

### 4. Проверка работы (Hardware Verification Suite)
На устройстве запускается автоматический набор проверок (22 контрольных инварианта):

```sh
MINI_HOST=192.168.1.110 MINI_SSH_KEY=~/.ssh/id_ed25519 ./scripts/verify_deploy.sh
```

## Безопасность и приватность

- Все API-ключи, токены умного дома и учётные данные хранятся исключительно локально на вашем компьютере и в памяти устройства в файле `.env`.
- Локальный KWS обрабатывает ключевое слово прямо на процессоре колонки. Микрофонный поток передаётся в облако только после активации.
